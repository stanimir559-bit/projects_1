# Публикуване в съществуващия Stan Projects Worker

Хранилище: https://github.com/stanimir559-bit/projects_1

Worker: https://projects.stanimir559.workers.dev/

Приложението се добавя като **strongman/strongman-arena.html**. Хъбът открива този HTML автоматично чрез GitHub tree API; основният `index.html` и другите проекти не се променят. Адресът е `/strongman/strongman-arena` или `/strongman/strongman-arena.html` според канонизирането на Cloudflare.

Самостоятелните локални състезания работят веднага след публикуване на статичния файл. За общите резултати между съдии са нужни следните настройки в Cloudflare.

## Еднократна настройка

1. В Cloudflare отворете **Storage & Databases → D1 SQL Database** и създайте база, например **strongman-scores**.
2. В SQL конзолата на тази база изпълнете съдържанието на **strongman-source/cloudflare/schema.sql**. Използват се само две таблици с префикс `sm_`.
3. В Worker **projects → Settings → Bindings** добавете **D1 database** с име **SM_DB**, свързано към новата база.
4. В **Settings → Variables and Secrets** добавете **secret** с име **SM_KEY**. Изберете случаен код от поне 16 символа. Това е кодът за съдиите; не го записвайте в GitHub, HTML, README или Wrangler конфигурацията. Настройката изисква публикуване на новата Worker версия.
5. PR добавя Worker entry point и запазва статичната директория на хъба. Маршрутът **/strongman/api/** се обработва от кода; останалите адреси продължават към статичните файлове.
6. След свързване на D1 и секрета публикувайте актуалната версия чрез съществуващата GitHub → Cloudflare връзка. При Wrangler CLI, ако се изисква ресурсите да са декларирани във файла, добавете `d1_databases` с `binding: "SM_DB"`, името и реалния `database_id` на създадената база. Не използвайте фиктивен ID. Запазете dashboard binding-ите при всяко следващо публикуване.

Локално проверено е, че без D1/секрет API връща ясен отказ `NOT_CONFIGURED`, без да пречи на статичния хъб или на офлайн състезанията. Няма автоматично създаден публичен код за достъп.

## Работа от телефона

Отворете приложението, подгответе състезанието, после **Свързване**. Адресът по подразбиране е **https://projects.stanimir559.workers.dev/strongman**. Първият съдия натиска **Създай обща сесия**, останалите — **Присъедини се** с техните имена и същия код. Използвайте една страница на устройство.

HTTPS версията кешира само папката на Strongman Arena за офлайн отваряне; не кешира/прехваща хъба и другите проекти. При прекъсване локалните операции изчакват, после се обединяват с проверка за конфликт. Можете да изтеглите HTML за самостоятелна офлайн работа.

## Проверка след публикуването

- Хъбът и старите HTML проекти се отварят.
- Приложението се появява в списъка на хъба.
- Общата сесия може да се създаде и отвори на втори телефон.
- Промяна на резултат се появява на другото устройство, а едновременно редактиране на същия резултат не води до тихо презаписване.
- При рефреш състезанието и историята се запазват; при кратко прекъсване черновите се запазват.

## Архитектура

Точките се изчисляват от един и същ модул в браузъра и в Worker. D1 пази целия текущ документ, включително история и undo/redo. Големите документи се разделят на части под лимита на D1 за ред. Атомарен D1 batch и проверка на версията предотвратяват загуба на едновременни промени. Кодът на съдиите се проверява от Worker; данните за състезанието не се записват в публичното GitHub хранилище.

Използва се една обща активна сесия. Изтегляйте архиви. Cloudflare заявките и D1 са подчинени на ограниченията на плана ви; тук не е активиран платен план.
